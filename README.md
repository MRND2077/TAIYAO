# 客户跟进看板 · 通用模板

把一份客户表格，变成一张**能点、能筛、能下钻到原始资料**的看板。

单文件 HTML —— 不需要服务器、不需要数据库、不需要联网。双击打开就能用。

> 打开 `index.html` 即可看到效果。没有数据也没关系，它会先用一份虚构演示数据展示全部功能。

---

## 它能做什么

- **每个统计数字都能点**。点"红灯 5 位"，列出这 5 位是谁；点分布条的任一段，列出构成这一段的客户。
- **每张卡片都能打开**。点客户卡片，弹出这位客户的原始档案与分析报告。
- **名单里标出缺什么**。每个客户单独标注「明确缺：联系方式」和「未记录：互动天数」—— 这两件事不一样。
- **数字是算出来的，不是写死的**。改一条记录，全页的 KPI、圆环、分布条、名单会同步变化。
- **字段名可以改成你的说法**。「关键动作 1」可以改成「已取得联系方式」，改完立即生效。
- **空壳设计**。不导入数据是通用版；导入自己的资料，它就是你的业务版。

## 两条使用路径

### 路径 A：直接用（不需要写代码）

1. 下载 `index.html`
2. 双击打开
3. 点「先看通用演示版」，看看它长什么样
4. 点「导入我的客户资料」，粘贴或上传你的数据
5. 在右上角「字段设置」里，把字段名改成你自己的业务叫法

导入的数据会存在浏览器本地，下次打开还在。「重新选择数据」可以清空重来。

### 路径 B：让 AI 帮你改

把 [`prompt.md`](prompt.md) 里的提示词整段复制给 AI（Claude / GPT / 其他都行），把它生成的结果
替换掉 `<...>` 里的内容。提示词里写清了完整规格和验收清单。

适合需要换布局、换指标、换行业语义的场景。

### 路径 C：改源码

```bash
# 用自带演示数据生成 index.html
python src/build.py

# 用自己的数据生成
python src/build.py data/mine.json

# 指定输出文件
python src/build.py data/mine.json my-board.html
```

改 `src/template.html` 可以调整页面结构和样式，`__DATA__` 是数据注入点。

## 数据格式

只需要一份 JSON。除 `name` 和 `level` 外，所有字段都可以缺，缺了会显示为「未记录」而不是空白。

```json
{
  "meta": {
    "scope": "10-09 ~ 10-16",
    "generatedAt": "2026-10-16"
  },
  "fields": {
    "title": "客户跟进看板",
    "client": "客户",
    "role": "联系人角色",
    "profile": "客户画像",
    "a1": "关键动作 1",
    "a2": "关键动作 2",
    "a3": "关键动作 3",
    "rep": "互动活跃度",
    "updated": "数据截止"
  },
  "records": [
    {
      "id": "C01",
      "name": "客户 01",
      "account": "acme_pm",
      "role": "决策人",
      "profile": "50 人团队 · 已试用",
      "level": "g",
      "a1": 1,
      "a2": 0,
      "a3": -1,
      "lastContact": 3,
      "note": "",
      "updatedAt": "10-15"
    }
  ],
  "docs": {
    "C01": {
      "source": "C01-原始档案.md",
      "sourceReport": "C01-分析报告.md",
      "folder": "C01 资料目录",
      "updatedAt": "10-15",
      "arch": "<h2>客户 01 · 原始档案</h2><p>这里放档案原文，可以是 HTML</p>",
      "report": "<h2>客户 01 · 分析报告</h2><p>这里放分析结论</p>"
    }
  }
}
```

### 字段说明

| 字段 | 位置 | 含义 | 取值 |
|---|---|---|---|
| `id` | records | 唯一主键，用于关联 `docs` | 任意唯一字符串 |
| `name` | records | 客户名称 | **必填** |
| `account` | records | 渠道账号 / 昵称 | 可空 |
| `role` | records | 联系人角色 | 可空 |
| `profile` | records | 客户画像 | 可空 |
| `level` | records | 健康度分级 | **必填**，`g` / `l` / `y` / `r` |
| `a1` `a2` `a3` | records | 三个关键动作 | `1` 已完成 / `0` 明确未完成 / `-1` 未记录 |
| `lastContact` | records | 最近互动间隔（天） | 非负整数，`-1` 表示未记录 |
| `note` | records | 备注 | 可空 |
| `updatedAt` | records | 该条数据的截止日期 | 可空 |
| `docs` | 顶层 | 原始资料，以 `id` 为 key | 可省略 |
| `arch` / `report` | docs | 两份原文，支持 HTML | 可空 |
| `fields` | 顶层 | 自定义字段名 | 可省略，省略则用通用名 |

### 关于三个关键动作

`a1` `a2` `a3` 是三个"完成 / 未完成"的档位，具体是什么完全由你定，例如：

- 销售：已取得联系方式 / 已加入客户群 / 已完成首次体验
- 教培：已加微信 / 已进学习群 / 已提交作业
- 房产：已电话沟通 / 已带看 / 已出方案

只要在 `fields` 里写好它们叫什么，看板就会用你的叫法。

## 常见问题

**数据会被上传到哪里吗？**
不会。整个看板是纯前端，数据只在你的浏览器里。断网也能用。

**刷新后导入的数据还在吗？**
在。存在浏览器本地（localStorage）。换浏览器或换机器就不在了，需要重新导入。

**能放到服务器上吗？**
能，它就是个静态文件。放在 GitHub Pages、对象存储、公司内网都行。

**支持多少人？**
演示数据是 33 位。实测几百位没问题，卡片网格会自动滚动。上千位建议先按分级拆成多份。

**可以不要演示数据吗？**
可以。把 `data/demo.json` 换成你的数据，重新跑 `src/build.py`。生成的看板打开就直接是你的数据。

## 设计说明

这份看板有几条坚持，写在 [`prompt.md`](prompt.md) 第二节里。简述：

- **判据要写在页面上。** 只给"15 位绿灯"是结论，给出"绿灯 = 互动充分且资料齐备"才是判据 —— 使用者才能复核。
- **三态不能合并。** 「没记录」和「明确缺失」是两件事，前者要补数据，后者要走别的路。
- **数字必须实时算。** 手写死的数字迟早和名单对不上。
- **主键用 ID 不用姓名。** 重名会让数据串位，而且很难发现。
- **演示数据必须虚构。** 它会被下载、转发、截图。
