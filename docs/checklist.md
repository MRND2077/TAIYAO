# 交付验收清单

拿到一份看板（自己做的，或者 AI 生成的），逐条走一遍。全部通过才算交付完成。

## 一、关联是否真的通了

- [ ] **点圆环或图例** —— 能列出该分级的客户名单
- [ ] **点分布条任一段** —— 能列出构成这一段的客户
- [ ] **点客户卡片** —— 能看到该客户的原文资料，不是二次概括
- [ ] **资料弹窗的标签页** —— 档案 / 报告 两个都能切换
- [ ] **点矩阵里的符号** —— 能列出同状态的客户
- [ ] **点行动清单里的数字** —— 能列出对应的客户

## 二、名单弹层是否合格

- [ ] 每一档带**业务解释**，不只是罗列名单
- [ ] 顶部有「在明细区只看这 N 位」按钮，点了能筛下面主区
- [ ] 每一行分别标注「明确缺：xxx」（红）与「未记录：xxx」（灰）
- [ ] 点名单里的某一行，能继续下钻到该客户的资料

## 三、口径与判据是否可复核

- [ ] 页头有：数据范围、截止时间、生成时间、风险摘要
- [ ] 每一档分级旁边写明了判据
- [ ] 每个比率都有分母
- [ ] 未更新的数据有显式标注（如「沿用上一轮」）
- [ ] 异常事项单独成块，每条附**触发规则**

## 四、三态有没有被合并

- [ ] 「已具备」用 ✓、「明确缺失」用 ✗、「未记录」用 ?
- [ ] 数值字段用 -1 表示未记录，没有拿 0 冒充
- [ ] 名单和矩阵里也贯彻了这三态，不只是表格里

## 五、空壳与数据接入

- [ ] 打开先出欢迎层，有「导入资料」和「看演示」两个入口
- [ ] 导入支持粘贴 JSON 和上传文件
- [ ] 导入校验能指出错在第几条、哪个字段
- [ ] 提供「下载示例模板」
- [ ] 有「重新选择数据」入口
- [ ] 字段名可以改，改完立即生效
- [ ] **不导入数据时，字段显示为通用名**（关键动作 1/2/3），不是行业专有说法

## 六、演示数据是否干净

- [ ] 客户名是「客户 01」这类占位，不是真实姓名
- [ ] 账号、画像等可识别字段已清空
- [ ] 行业专有角色已换成通用角色
- [ ] 证据弹窗里是占位说明，不是真实材料
- [ ] **页面手写的示例值**（字段说明表、placeholder、下载模板）也是虚构的

> 自查方法：把原始数据里所有客户名、昵称、原文片段做成清单，逐条在产出文件里搜一遍。
> 更彻底的做法是把原文切成 6 字窗口做指纹比对 —— 任何一段原文残留都会被抓出来。

## 七、反例检验（最关键的一条）

- [ ] **随便改掉主表里一条记录的分级，刷新后 KPI、圆环、分布条、名单全部跟着变**

变不了，说明那个数字是手写死的，前面的关联都是假的。

## 八、缓存与稳定性

- [ ] 更新数据后重新打开，看到的是**当前版本**的数据，不是上次缓存的
- [ ] 清除浏览器缓存后打开，功能正常
- [ ] 断网状态下打开，功能正常
- [ ] 没有外部依赖（无 CDN、无外部字体、无接口调用）

---

## 常见失败现象对照

| 现象 | 大概原因 |
|---|---|
| 点了按钮没反应 | 用 `hidden` 属性控制显隐时，CSS 里写了 `display`，覆盖了 `[hidden]{display:none}` |
| 更新文件后看到的还是旧数据 | localStorage 没带数据版本号 |
| 页面白屏 / 功能全失效 | 数据里含 `</script>` 序列，把脚本标签提前闭合了（注入时要转义 `<`） |
| 数字和名单对不上 | 数字是硬编码的，没有从主表实时计算 |
| 某个客户点开是空白 | 缺关联兜底 —— 查不到资料时应显式提示，不能白屏 |
| 重名客户数据串位 | 用姓名而不是唯一 ID 做主键 |
